# 健康监测首页仪表盘、趋势页与提醒链路设计

日期：2026-06-16  
状态：待评审

## 1. 文档目标

本文档用于定义健康监测 App 新一轮首页与提醒体验升级的设计边界，覆盖以下三部分：

- 首页仪表盘的信息结构、交互行为与数据口径
- 趋势分析页的内容组织、图表切换与智能洞察生成方式
- 规则提醒到本地通知的投递链路，以及最小可用勿扰设置

本次设计以当前 Flutter 基线、真实采集链路、现有规则引擎与提醒模型为前提，优先采用增量演进，不推翻既有 `overview`、`briefing`、`profile`、`reminders` 结构。

## 2. 需求范围

本次确认的产品范围如下：

### 2.1 首页仪表盘

- 综合健康分环形进度条
- 步数卡片
- 久坐卡片
- 屏幕卡片
- 环境快照条
- AI 建议气泡

### 2.2 趋势分析页

- 独立二级页，不替换当前简报页
- 默认展示近 7 天步数趋势
- 支持切换久坐、屏幕、环境趋势
- 图表下方展示智能洞察文案

### 2.3 提醒弹窗

- 复用现有规则引擎可触发的提醒类型
- 通过本地通知投递
- 遵循用户设定的勿扰时段

## 3. 关键决策摘要

### 3.1 首页采用“结论优先，细节后置”的结构

首页不做满屏数据面板，而是保持以下顺序：

1. 综合健康分环形区
2. 步数 / 久坐 / 屏幕 3 张关键卡片
3. 环境快照条
4. AI 建议气泡

设计目标是先给用户一个可解释的整体结论，再提供进入细节的入口，不把首页做成高压式 dashboard。

### 3.2 趋势页作为首页进入的独立二级页

保留现有 `briefing` 页，不将其替换为趋势页。  
综合健康分点击后进入新的趋势分析页，首页卡片的局部细节通过底部浮层承接。

### 3.3 AI 建议气泡使用真 LLM 直连

AI 建议气泡不再只做规则模板填充，而是新增真实 LLM 调用链路。  
但 LLM 输入只允许使用“当天聚合后的摘要特征”，不直接发送原始音频、逐条传感器样本或可回放历史。

### 3.4 提醒类型不扩充，优先打通投递链路

本次不新增新的提醒类型，继续复用现有规则引擎已能输出的提醒分类。  
重点是补齐“提醒记录 -> 本地通知 -> 勿扰判断 -> 去重/降级”的完整链路。

### 3.5 勿扰设置采用最小可用方案

在“我的”页现有提醒偏好区域内补齐：

- 勿扰开关
- 开始时间
- 结束时间

不新增复杂偏好体系，不单开设置详情页。

## 4. 首页仪表盘设计

## 4.1 页面结构

首页 `OverviewPage` 更新后的结构如下：

1. 页面头部
2. 综合健康分环形区
3. 步数 / 久坐 / 屏幕三卡并列区
4. 环境快照条
5. AI 建议气泡

首页不再把提醒列表作为主区块展示。提醒的实时触达由系统通知承担，历史记录仍从“我的”页进入。

## 4.2 综合健康分

综合健康分满分 100，使用固定权重计算：

- 步数达成率：40%
- 久坐控制得分：40%
- 屏幕控制得分：20%

点击综合健康分后跳转至趋势分析页。

### 4.2.1 计算规则

步数得分：

- 目标步数固定为 `6000`
- 得分 = `min(今日步数 / 6000, 1.0) * 100`

久坐控制得分：

- `120 分钟` 内视为满分
- 超出后线性扣分
- 最低不低于 0 分

屏幕控制得分：

- `180 分钟` 内视为满分
- 超出后线性扣分
- 最低不低于 0 分

最终健康分：

- `步数得分 * 0.4 + 久坐得分 * 0.4 + 屏幕得分 * 0.2`

该计算器保持纯 Dart，实现为可单测的独立模块。

## 4.3 三张核心卡片

### 4.3.1 步数卡片

展示内容：

- 今日步数
- 目标步数（默认 6000）
- 达成百分比

交互行为：

- 点击卡片底部或卡片主体，弹出过去 7 天步数柱状图浮层
- 浮层顶部保留今日步数、目标值与达成百分比

### 4.3.2 久坐卡片

展示内容：

- 今日累计久坐时长（分钟）
- 单次最长久坐

交互行为：

- 点击后弹出“今日久坐时段分布时间轴”浮层
- 浮层展示今日久坐片段、最长片段和时间分布

### 4.3.3 屏幕卡片

展示内容：

- 今日亮屏总时长
- 相比昨日变化箭头与变化值

交互行为：

- 点击后弹出分时段使用分布浮层
- 浮层展示今日各时段使用密度与总时长

### 4.3.4 三张卡片的统一交互约束

三张卡片统一使用底部浮层承接细节，不新增二级详情页。  
三种浮层共用统一壳组件，统一标题区、关闭方式、空态文案与说明样式。

## 4.4 环境快照条

环境快照条以图标加文字形式展示当前环境状态：

- 光照：`🌞 明亮 / 🌥 舒适 / 🌙 过暗`
- 噪音：`🔊 嘈杂 / 🔉 正常 / 🔇 安静`

数据策略：

- 有实时值时优先展示实时值
- 无实时值时回退到最近一次有效样本
- 再无数据时展示等待采集态

环境快照条只负责“当前感受”，不承担趋势解释与风险打分，趋势解释交由趋势页。

## 4.5 AI 建议气泡

AI 建议气泡位于首页下部，展示一句个性化建议文案。

行为约束：

- 每日首次打开首页时请求一次 LLM
- 同一天内本地缓存结果
- 同一天重复进入首页不重新生成

### 4.5.1 LLM 输入边界

允许发送给 LLM 的摘要特征包括：

- 今日步数
- 今日久坐分钟数
- 今日亮屏分钟数
- 当前环境状态
- 综合健康分
- 当日最高优先级规则结论
- 是否存在提醒触发

不允许发送：

- 原始音频
- 原始传感器逐条样本
- 可回放历史数据
- 不必要的高精度用户轨迹明细

### 4.5.2 降级策略

以下情况直接降级为规则模板文案：

- 网络失败
- 模型调用超时
- 配额受限
- 当日聚合数据不足

## 5. 趋势分析页设计

## 5.1 页面定位

趋势分析页 `TrendAnalysisPage` 是首页进入的独立二级页，职责单一：

- 展示近 7 天关键趋势
- 给出一段智能洞察解释

不承接今日卡片级别的即时解释，不替代当前简报页。

## 5.2 页面结构

建议结构如下：

1. 顶部返回与标题
2. 趋势 Tab
3. 单一主图表区域
4. 智能洞察文案区域

图表区域只在一个维度内展示一个主图，不做多图并列。

## 5.3 Tab 顺序

固定为：

1. 步数
2. 久坐
3. 屏幕
4. 环境

默认进入“步数”。

## 5.4 各 Tab 内容

### 5.4.1 步数趋势

- 近 7 天步数折线图或轻量折线表现
- 强调目标达成情况和波动节奏

### 5.4.2 久坐趋势

- 近 7 天久坐时长柱状图
- 强调高久坐日与改善趋势

### 5.4.3 屏幕趋势

- 近 7 天亮屏时长折线图
- 强调是否收敛或上升

### 5.4.4 环境趋势

- 近 7 天环境健康分趋势
- 分数由每日光照与噪音摘要聚合计算
- 本轮仅用于观察趋势，不引入新的环境提醒类型

## 5.5 智能洞察文案

图表下方固定展示一段轻量洞察文案，例如：

- “过去一周你有 3 天步数超过 6000，周三最活跃。”
- “最近两天久坐时长明显回落，节奏正在变稳。”

洞察生成方式：

- 优先采用模板化聚合逻辑生成
- 不要求趋势页也走真 LLM

这样可以降低成本和抖动风险，把真 LLM 重点留给首页建议气泡。

## 6. 数据模型与服务边界

## 6.1 新增聚合层

现有 `HealthInsightService` 仍然保留，继续负责规则输入构建、规则评估与基础快照。  
在其之上新增更贴近产品展示的聚合层，不让页面直接拼接业务口径。

## 6.2 建议新增的领域/UI 模型

### 6.2.1 DashboardSnapshot

承载首页所需完整数据，至少包含：

- `healthScore`
- `stepCard`
- `sedentaryCard`
- `screenCard`
- `environmentSnapshot`
- `dailyAdviceBubble`
- `trendEntryState`

### 6.2.2 TrendSnapshot

承载趋势页所需数据，至少包含：

- 当前选中 Tab
- 近 7 天序列
- 图表标题
- 单位
- 空态文案
- 智能洞察文案

### 6.2.3 ReminderDeliveryPlan

承载通知投递决策结果，至少区分：

- 立即发送
- 勿扰中不发送但记录保留
- 权限缺失不发送但记录保留

### 6.2.4 NotificationPreference

承载最小可用勿扰设置：

- `enabled`
- `startTime`
- `endTime`

## 6.3 建议新增的服务

### 6.3.1 DashboardService

负责首页完整快照拼装，输出 `DashboardSnapshot`。

### 6.3.2 TrendAnalysisService

负责近 7 天趋势聚合与趋势洞察生成，输出 `TrendSnapshot`。

### 6.3.3 AiSuggestionService

负责：

- 构建 LLM 输入摘要
- 调用真 LLM
- 缓存当日建议
- 失败时降级为模板文案

### 6.3.4 ReminderDeliveryService

负责：

- 读取待投递提醒
- 结合勿扰设置进行判断
- 输出投递计划

### 6.3.5 LocalNotificationService

负责：

- 初始化本地通知能力
- 执行实际通知发送
- 屏蔽平台细节

## 7. 提醒链路与勿扰设置

## 7.1 提醒生成与存储

规则引擎继续按当前方式产出 `ReminderRecord`。  
本轮不新增提醒类型，只复用现有规则提醒分类与原生风险事件同步结果。

## 7.2 通知投递链路

建议链路如下：

1. 规则/事件层生成 `ReminderRecord`
2. 投递决策层读取提醒记录与勿扰设置
3. 通知执行层通过 `flutter_local_notifications` 发送

页面层不直接决定“发不发通知”。

## 7.3 勿扰设置落点

勿扰设置放在 `ProfilePage` 现有“提醒与显示偏好”区域内，包含：

- 勿扰开关
- 开始时间
- 结束时间
- 一句说明文案

说明文案需明确：

- 勿扰时段内不会主动推送提醒
- 提醒记录仍会保留

## 7.4 通知文案要求

通知文案必须保持亲切、非命令式、可解释。  
应优先使用生活化表达，例如：

- “可以活动一下啦，身体会更舒服一些。”
- “现在让眼睛停一停，等会儿再看手机也来得及。”

不使用压迫式、命令式语气。

## 8. 降级策略

### 8.1 数据不足

- 趋势页无近 7 天数据时展示明确空态，不画假图
- 首页某一维度无数据时，该卡片展示降级态，不影响其他模块

### 8.2 实时环境缺失

- 优先使用实时值
- 回退到最近样本
- 再回退到等待采集态

### 8.3 LLM 失败

- 回退到规则模板建议
- 首页不因 LLM 失败而留空

### 8.4 通知权限缺失

- 提醒继续入库
- 不发系统通知
- 在“我的”页保留轻提示

### 8.5 Usage Access 缺失

- 屏幕卡与屏幕趋势进入降级态
- 不影响首页其他模块与规则链路运行

## 10. 实现约束

本次实现需要遵守以下边界：

1. 页面层不自己计算健康分，不自己拼近 7 天序列
2. 趋势页只消费历史聚合数据，不直接读取实时传感器流
3. AI 服务只读取摘要特征，不直接发送原始感知数据
4. 通知是否发送由投递服务统一判断，页面层不介入策略
5. 环境条允许“实时优先、最近样本兜底”，但必须有明确等待态

## 12. 结论

本次设计采用“首页结论优先、趋势页承接细节、提醒链路服务化、AI 建议独立接入”的方案，可以在不打乱当前 Flutter 结构的前提下，完成以下升级：

- 首页从“静态概览卡”升级为更完整的仪表盘入口
- 趋势分析页成为 7 天历史变化的统一承载页
- 提醒从“仅记录”升级为“记录 + 本地通知 + 勿扰控制”的闭环
- AI 建议从规则模板升级为真 LLM 直连，并保留明确降级路径

该方案保持了产品“可解释、低打扰、非医疗诊断、隐私优先”的核心语气，同时为后续实现计划和 TDD 拆分提供了清晰边界。
