# `health-monitor-app-design` Flutter UI/UX 设计落地规范

日期：2026-06-22
状态：正式设计与交互基准

## 1. 文档目标

本文档把当前高保真 Pencil 设计稿转换为可直接指导 Flutter 开发、状态建模、交互实现、测试和视觉验收的统一规范。

本文档覆盖：

- 首页
- 趋势分析
- 每日简报
- 提醒记录、提醒详情与提醒原因解释
- “我的”与权限、勿扰、提醒偏好、数据说明
- 一级导航与二级页面
- 加载、刷新、错误、空数据、部分数据、权限缺失和平台不支持状态
- 动效、手势、无障碍与适配

本文档只定义产品界面、交互契约和 Flutter 落地边界，不改变已有领域规则、隐私约束和平台能力边界。

### 2.2 规范优先级

后续 UI 实现按以下顺序解释设计要求：

1. `docs/designs/health-monitor-app-design.pen`：最高优先级视觉源
2. 本文档：最高优先级交互、状态与 Flutter 落地规范
3. `docs/superpowers/specs/2026-06-21-health-monitor-daily-rhythm-ui-spec.md`：首页节奏轴专项补充
4. `docs/superpowers/specs/2026-06-16-health-monitor-dashboard-trends-reminder-design.md`：业务背景与数据链路参考
5. 其他旧版 UI/UX 文档：历史参考

### 2.3 冲突处理原则

- 布局、颜色、层级、圆角、间距和视觉重心以 `.pen` 文件为准。
- 数据口径、权限行为、隐私策略和平台差异以真实业务模型及最新技术文档为准。
- 设计稿中的日期、分数、步数、用户名和趋势只用于展示，不得作为业务常量。
- 设计稿中出现但当前产品尚不存在的账号、云同步、用户头像等能力，不得仅因视觉稿存在而伪造实现。
- 真实数据不足时必须显示降级状态，不得为了还原设计稿而绘制虚假趋势。
- 页面层不得直接读取或解释原始传感器样本。

## 3. 产品体验原则

### 3.1 核心气质

产品应呈现为：

`温和、可解释、低打扰的生活健康助手`

不应呈现为：

- 医疗诊断工具
- 高压行为监控面板
- 充满警报和风险颜色的后台系统
- 强迫用户完成任务的打卡产品

### 3.2 信息表达顺序

所有主要页面遵循：

1. 先给结论
2. 再给变化或依据
3. 最后给一个可执行动作

同一时刻只突出一个主要动作。次级建议不得与主要动作使用相同视觉权重。

### 3.3 文案原则

- 使用生活化中文，不使用底层传感器术语。
- 使用“可以”“建议”“试试”，避免“必须”“异常”“警告”。
- 不使用医学诊断词汇。
- 每条提醒都必须能解释“为什么现在提醒”。
- 数据不足时明确说明不足，不把“未知”包装成“正常”。

## 4. 全局信息架构

### 4.1 一级导航

一级导航固定为四个 Tab：

| 顺序 | Tab | 路由 | 页面 |
| --- | --- | --- | --- |
| 1 | 首页 | `/overview` | `OverviewPage` |
| 2 | 趋势 | `/trends` | `TrendAnalysisPage` |
| 3 | 简报 | `/briefing` | `BriefingPage` |
| 4 | 我的 | `/profile` | `ProfilePage` |

趋势页属于一级页面：

- 不显示返回按钮。
- 通过底部导航直接进入。
- 从首页跳入趋势页时，仍使用同一一级页面实例，但允许携带初始维度和范围。

### 4.2 一级导航交互

#### 点击非当前 Tab

1. 立即显示目标 Tab 激活态。
2. 使用 `180ms` 淡入或轻微缩放切换页面。
3. 保留其他 Tab 的滚动位置和会话内选择状态。
4. 不因为单纯切换 Tab 而强制刷新数据。

#### 再次点击当前 Tab

1. 页面平滑滚动到顶部。
2. 不主动请求新数据。
3. 如果页面已处于顶部，不执行可见动画。

#### 系统返回

- 一级 Tab 之间不形成返回栈。
- Android 在一级页面按系统返回时退出当前页面栈或退到系统后台。
- 不按“趋势 → 首页 → 简报”的访问顺序循环回退。

### 4.3 二级页面

保留：

- `/reminders`
- `/reminders/detail`
- `/reminders/explanation`
- `/diagnostics`
- `/permission-denied`
- `/data-insufficient`

二级页面规则：

- 显示顶部返回。
- 不显示一级底部导航。
- 返回时优先 `pop` 当前导航栈。
- 无可返回页面时，提醒相关页面回到 `/profile`，其他页面按所属 feature 回到合理入口。

以下交互优先使用底部弹层，不新增路由：

- 权限用途说明
- 日期选择
- 提醒筛选
- 指标详情
- 节奏节点解释
- 勿扰设置
- 提醒偏好

## 5. 全局视觉规范

### 5.1 设计基准

| 项目 | 数值 |
| --- | --- |
| 基准画板 | `390 × 844 dp` |
| 页面水平边距 | `18 dp` |
| 主内容宽度 | `354 dp` |
| 基础间距 | `4 dp` |
| 相关内容间距 | `8–12 dp` |
| 主区块间距 | `16–24 dp` |
| 最小触控区域 | `44 × 44 dp` |

页面必须使用系统安全区。不得把自绘状态栏作为正式 Flutter 实现的一部分。

### 5.2 颜色 Token

建议统一写入现有 ThemeExtension，不允许各 feature 继续维护重复颜色常量。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#FAF5EC` | 页面背景 |
| `surface` | `#FFFFFF` | 主卡片和列表表面 |
| `surfaceSoft` | `#F8F3EA` | 次级表面、结论条 |
| `borderSubtle` | `#DDD8CF` | 柔和描边 |
| `divider` | `#ECE7DE` | 分组行分隔 |
| `textPrimary` | `#242724` | 标题和主要数字 |
| `textSecondary` | `#737873` | 说明和辅助标签 |
| `sage` | `#6F9A72` | 品牌、活动、良好状态 |
| `sageSoft` | `#DDEBDD` | 活动图标底 |
| `sand` | `#D7B27B` | 姿势维度 |
| `sandSoft` | `#F3E6D2` | 姿势图标底 |
| `coral` | `#DF7B6E` | 环境噪音维度 |
| `coralSoft` | `#F6DAD5` | 噪音图标底 |
| `blue` | `#72A7C4` | 数字生活维度 |
| `blueSoft` | `#DDECF3` | 数字生活图标底 |
| `orange` | `#F0A23B` | 当前时刻、待处理、主要行动 |

颜色不得作为状态的唯一表达方式，必须同时提供图标、标签或文字。

### 5.3 卡片和表面

#### 主卡

- 圆角：`26–28 dp`
- 背景：纯白
- 可选柔和描边：`borderSubtle`
- 两层阴影：
  - `color #3D392F0A, offset 0/3, blur 8`
  - `color #3D392F12, offset 0/14, blur 30`

#### 列表项

- 圆角：`20–22 dp`
- 高度按内容自适应
- 最小触控高度：`52 dp`

#### 规则

- 不允许在完整主卡内再嵌套另一张完整主卡。
- 分组内容优先使用同一白色表面和分隔线。
- 阴影只用于建立主表面层级，不得用于每一个小标签。

### 5.4 字体

| 层级 | 字号 | 字重 |
| --- | --- | --- |
| 首页主标题 | `30` | `w700` |
| 一级页面标题 | `18–22` | `w700` |
| 卡片主结论 | `18–20` | `w700` |
| 区块标题 | `14–16` | `w700` |
| 主要数字 | `28–46` | `w600–700` |
| 正文 | `12–14` | `w400–600` |
| 辅助说明 | `9–11` | `w400–500` |

中文使用系统无衬线字体。数字可使用 Inter 等宽特性，但不得为引入字体而破坏中文渲染一致性。

大字体模式：

- 不缩小字号以强行塞入。
- 卡片允许增高。
- 横向双栏在空间不足时改为纵向排列。
- 主要结论必须优先保证可读。

### 5.5 图标

- 使用 Flutter Rounded 图标体系。
- 视觉尺寸：`17–22 dp`
- 状态图标使用浅色圆形容器。
- 同一级图标保持相同线宽和填充风格。
- 无匹配系统图标时才新增授权 SVG。
- 图标按钮必须提供语义标签和不少于 `44 × 44 dp` 的点击区域。

## 6. 全局动效与手势

### 6.1 动效时长

| 场景 | 时长 |
| --- | --- |
| 按压反馈 | `100–150ms` |
| Tab / Segment 切换 | `180–220ms` |
| 字段内容替换 | `220ms` |
| 折叠展开 | `220ms` |
| 底部弹层进入 | `260ms` |
| 图表首次绘制 | 不超过 `500ms` |

### 6.2 动效规则

- 动效只解释状态变化，不循环播放。
- 数据刷新只更新发生变化的字段，不重播整页入场。
- 列表入场错峰最多应用于前 6 项。
- 开启系统“减少动态效果”后，只保留淡入淡出。
- 不使用弹跳、强缩放或持续脉冲制造焦虑。

### 6.3 手势规则

- 底部弹层支持下滑关闭和点击遮罩关闭。
- 正在保存关键设置时禁止误关闭，或先给出离开确认。
- 横向日期和图表手势不得抢占页面纵向滚动。
- 所有点击操作提供按下态。

## 7. 首页 `OverviewPage`

### 7.1 页面目标

首页回答：

`我今天整体状态如何，现在最值得做什么？`

### 7.2 页面结构

1. 标题与个人感知入口
2. 生活节奏轴
3. 今日结论与状态分
4. 四维健康摘要
5. 当前行动建议
6. 一级导航

### 7.3 页面头部

- 标题：`今天的节奏`
- 副标题使用当前最高优先级的温和提示。
- 右侧“个人感知”入口触控高度至少 `44 dp`。

个人感知入口点击：

1. 打开权限与感知状态底部层。
2. 显示当前参与分析的能力。
3. 缺失权限提供对应处理入口。
4. 不创建无业务承接的新页面。

### 7.4 生活节奏轴

#### 数据映射

节奏轴最多展示：

- 活动事件
- 姿势/久坐事件
- 环境噪音事件
- 数字生活事件
- 当前时刻

页面层只消费 `DailyRhythmUiModel`，不得从原始样本推导节点。

#### 首次进入

1. 曲线淡入。
2. 节点按时间顺序淡入。
3. 当前时刻节点最后出现。
4. 整体时长不超过 `500ms`。

#### 普通节点点击

每个节点视觉尺寸可小于 `44 dp`，但命中区域必须至少 `44 × 44 dp`。

点击后打开事件说明底部层，内容顺序：

1. 时间和维度
2. 状态标题
3. 判断依据摘要
4. 一条行动建议
5. 数据质量说明（如需要）

#### 当前节点点击

打开“当前状态”底部层：

- 当前时间
- 最近一个已形成的节奏判断
- 当前最值得做的动作
- 若无足够数据则显示“当前数据仍在积累”

#### 端点

- 早晨和晚间图标只表达时间范围。
- 不响应点击。
- 不提供伪入口。

#### 数据缺失

- 对应节点改为灰色虚线。
- 状态文字显示“数据不足”。
- 点击后说明缺失原因和受影响能力。
- 不绘制虚假趋势。

#### 当前时间定位

- 按当天时间在有效范围内计算标准化位置。
- 当前节点不得与普通节点强制共用坐标。
- 发生视觉重叠时，当前节点沿曲线做最小偏移，并用连接线保持时间语义。

#### 绘制边界

曲线、节点和命中检测使用 `CustomPainter`：

- Painter 只接收标准化坐标、颜色和状态。
- Provider 和仓库不得注入 Painter。
- 语义节点由外层 Widget 提供，不依赖画布本身完成无障碍。

### 7.5 今日结论卡

#### 展示

- 主结论
- 今日状态分
- 状态标签
- 数据质量说明（如存在）

#### 点击

- 卡片主体和分数区域行为一致。
- 点击进入 `/trends`。
- 默认选择与当前主要结论关联度最高的维度。
- 未提供关联维度时默认活动。

#### 刷新

- 分数和结论使用 `220ms` 淡入替换。
- 不重播页面入场动画。
- 刷新期间保留旧值。

#### 空数据

- 隐藏分数。
- 标题改为“数据正在积累”。
- 显示缺失维度或预计可用条件。

### 7.6 四维健康摘要

每行包含：

1. 图标
2. 维度名和主值
3. 微型趋势
4. 状态
5. 辅助说明
6. 进入箭头

#### 活动

- 点击打开活动详情底部层。
- 展示目标、当前步数和近 7 天变化。

#### 姿势

- 点击打开久坐详情底部层。
- 展示累计久坐、最长片段和时段分布。

#### 环境噪音

- 点击进入趋势页。
- 自动选择环境维度和近 7 天范围。

#### 数字习惯

- 点击打开屏幕使用详情底部层。
- 展示总时长、日间/夜间分布和数据质量。

#### 缺失数据

- 行仍保持可点击。
- 点击后展示权限或数据不足说明。
- 不进入空白详情。
- 微型曲线不响应独立点击。

### 7.7 行动建议

整张卡和右侧按钮为同一操作。

#### 久坐建议

- 打开 3 分钟活动引导底部层。
- 不启动强制倒计时。
- 用户可点击“我已活动”完成。

#### 屏幕建议

- 打开休息说明层。
- 提供“稍后提醒”或“我知道了”，前提是业务已支持对应提醒状态。

#### 环境建议

- 展示可执行建议。
- 不直接打开系统设置。

#### 完成状态

- 存在关联提醒时可更新为 `ReminderResponse.taken`。
- 成功后显示轻量 SnackBar。
- 失败时保留原卡片并提供重试。

### 7.8 首页刷新

支持下拉刷新：

1. 保留旧内容。
2. 顶部显示轻量刷新状态。
3. 刷新成功执行字段级更新。
4. 刷新失败保留旧数据并提示“暂时无法更新”。
5. 不因为刷新失败清空已有内容。

## 8. 趋势分析 `TrendAnalysisPage`

### 8.1 页面层级

- 趋势是一级 Tab。
- 页面不显示返回按钮。
- 从首页进入时只改变当前 Tab 和初始筛选，不创建二级路由实例。

### 8.2 页面结构

1. 页面标题
2. 时间范围切换
3. 维度切换
4. 主趋势卡
5. 本期洞察
6. 每日对比
7. 一级导航

### 8.3 时间范围

新增：

```dart
enum TrendRange {
  days7,
  days30,
  days90,
}
```

默认近 7 天。

#### 点击范围

1. 立即更新选中态。
2. 保留旧图表并降低至约 `60%` 透明度。
3. 显示局部加载标识。
4. 请求对应维度和范围的数据。
5. 成功后用 `220ms` 替换。
6. 失败时恢复上一个有效范围，并显示错误提示。

每个维度在当前 App 会话内分别记忆最后选择的范围。

### 8.4 维度切换

| UI 标签 | 领域枚举 |
| --- | --- |
| 活动 | `TrendTab.steps` |
| 姿势 | `TrendTab.sedentary` |
| 噪音 | `TrendTab.environment` |
| 屏幕 | `TrendTab.screen` |

点击后更新：

- 选中下划线
- 维度色
- 图表标题
- 数值单位
- 图表序列
- 本期洞察
- 每日对比

切换维度：

- 不改变页面滚动位置。
- 有缓存时先显示缓存，再后台刷新。
- 快速连续切换只接受最后一次选择结果。
- 旧请求完成后不得覆盖当前选择。

### 8.5 主趋势图

#### 默认状态

- 默认高亮范围内最后一个有数据点。
- 显示范围摘要、当前值和变化。

#### 点击或拖动

1. 进入数据探查状态。
2. 显示垂直指示线。
3. 高亮最近的数据点。
4. 显示日期和数值浮层。
5. 手指离开后保留 1.5 秒。
6. 自动恢复默认高亮。

#### 无数据点

- 单点缺失不得使用 0 替代。
- 折线应断开或显示缺失标识。
- 全部无数据时显示明确空态。

#### 无障碍

- 图表提供整体文本摘要。
- 每个数据点可按日期和数值被屏幕阅读器读取。
- 不只通过曲线颜色表达维度。

### 8.6 本期洞察

- 最多展示三条。
- 默认不可点击。
- 只有存在对应详情时才显示箭头。
- 洞察加载失败不影响主图表。
- 文案由聚合逻辑生成，不展示原始样本或技术阈值。

### 8.7 每日对比

- 点击柱体高亮对应日期或聚合周期。
- 显示选中值。
- 默认高亮今天或最后一个有数据日期。
- 近 30 天按周聚合。
- 近 90 天按周或月聚合。
- 禁止在固定宽度内强行绘制 90 根不可读柱。

### 8.8 状态管理

建议状态键：

```dart
typedef TrendQueryKey = ({
  TrendTab tab,
  TrendRange range,
});
```

缓存按 `TrendQueryKey` 隔离。Provider 必须防止旧请求覆盖新状态。

## 9. 每日简报 `BriefingPage`

### 9.1 页面目标

简报页回答：

### 9.2 页面结构

### 9.3 日期选择模型

现有 `BriefingTimeRange.today/yesterday/recent7Days` 无法完整表达设计稿交互，需演进为：

```dart
sealed class BriefingSelection {

class BriefingDaySelection extends BriefingSelection {
  const BriefingDaySelection(this.date);
  final DateTime date;

class BriefingRecentDaysSelection extends BriefingSelection {
```

### 9.4 周日期栏

### 9.5 日历入口

- 只允许选择可查询日期。

### 9.6 简报主卡

- 日期
- 主结论
- 一句支持说明

2. 次级观察
3. 缺失维度
4. 数据质量
5. 一条明日建议

- 说明哪些数据仍在积累。

### 9.7 当日时间线

- 事件按时间升序。
- 使用固定维度色映射。
- 同一时间只展开一个事件。

点击事件：

### 9.8 今日总结

## 11. “我的” `ProfilePage`

### 11.1 页面定位

“我的”不是传统账号主页，而是：

`信任与控制中心`

页面应帮助用户理解：

- App 感知了什么
- 当前状态如何
- 为什么会提醒
- 哪些能力可以关闭
- 数据如何处理

### 11.2 页面结构

1. 问候区
2. 我的感知状态
3. 设置分组
4. 一级导航

### 11.3 问候区

根据本地时间显示：

- 05:00–11:59：早上好
- 12:00–17:59：下午好
- 18:00–04:59：晚上好

规则：

- 无账号系统时不显示退出登录。
- 无昵称时使用通用问候。
- 不虚构姓名和头像。
- 头像只有在存在用户资料能力时可点击。

### 11.4 我的感知状态

卡片必须分为三个互不覆盖区域：

1. 左侧综合分
2. 右侧近 7 天趋势
3. 底部状态结论

#### 分数区域

- 点击进入趋势页。
- 默认活动维度和近 7 天。

#### 趋势区域

- 点击进入趋势页。
- 保留近 7 天范围。
- 触控区域覆盖整个图表区域。

#### 结论区域

- 点击进入最高优先级关联维度。
- 无关联维度时进入活动趋势。

#### 数据状态

无真实数据：

- 隐藏分数。
- 显示“正在积累数据”。
- 趋势区域显示数据积累说明。

部分数据：

- 允许展示分数。
- 必须显示“部分维度暂缺”。
- 点击质量说明打开缺失维度解释。

布局验收必须单独检查分数、标签、趋势和底部结论无重叠。

### 11.5 权限与隐私

点击后打开二级页面或底部层，展示：

- 当前参与分析的能力
- 每项权限用途
- 不开启会失去什么
- 本地处理说明
- 不保存原始音频说明

权限状态：

#### `granted`

- 显示已开启。
- 点击只展示用途，不重复申请。

#### `denied`

1. 先展示中文用途说明。
2. 用户确认后触发系统申请。
3. 用户取消后保持降级运行。

#### `restricted`

- 说明系统已限制再次申请。
- 提供前往系统设置入口。

#### `unknown`

- 先重新读取状态。
- 状态确认后再决定按钮行为。

从系统设置返回时：

- 自动刷新权限状态。
- 只刷新受影响模块。
- 单项失败不影响其他设置项。

### 11.6 勿扰时间

设置行显示：

- 当前时间段
- 是否启用

点击打开底部层，包含：

- 启用开关
- 开始时间
- 结束时间
- 说明文案
- 保存按钮

规则：

- 关闭时保留时间值，但不生效。
- 开始与结束相同视为无效。
- 无效时禁用保存。
- 跨午夜合法，例如 `22:30–07:00`。
- 勿扰只阻止主动通知，不删除提醒记录。

保存流程：

1. 保存按钮进入加载态并防止重复点击。
2. 页面先显示新值。
3. 写入 Isar。
4. 成功后关闭弹层并显示 SnackBar。
5. 失败时回滚旧值，保留弹层并提供重试。

### 11.7 提醒偏好

首版只提供：

- 总提醒开关
- 久坐提醒
- 移动看屏提醒
- 夜间使用提醒
- 环境噪音提醒

规则：

- 关闭某类提醒后不删除历史记录。
- 不提供复杂频率或阈值设置。
- 总开关关闭时子项保留原值但不可编辑。
- 恢复总开关后恢复原子项配置。

### 11.8 数据与存储

当前无正式云同步能力，因此：

- 设计稿中的“已同步到云端”改为“本地处理”。
- 不显示虚假同步状态。
- 点击后展示本地存储、数据保留和清理说明。
- 清理操作必须二次确认，并明确影响范围。

未来正式接入账号和云同步后，再扩展该入口。

### 11.9 关于我们

二级页展示：

- 应用版本
- 产品能力说明
- 隐私政策
- 非医疗诊断声明
- 开源许可（如适用）

### 11.10 退出登录

当前无账号体系：

- 不展示退出登录。
- 不保留不可用占位。

## 14. Riverpod 状态规则

### 14.1 缓存优先

- 页面存在同查询键缓存时先显示缓存。
- 后台刷新失败不清空缓存。
- 缓存内容必须标记对应维度、范围或日期，避免串页。

### 14.2 防止竞态

- 快速切换时只接受最后一个查询键结果。
- 异步请求返回后先确认当前查询键。
- 旧请求不得覆盖新状态。

### 14.3 字段级更新

- 使用 `select` 或拆分 Provider 降低无关重建。
- 单一维度 revision 只刷新对应模块。
- 页面不得因一个维度失败而重建全部内容为空态。

### 14.4 显式重试

- 错误卡的重试只 invalidate 对应 Provider。
- 权限变化后只 invalidate 受影响数据。
- 下拉刷新可以批量刷新当前页面所依赖的聚合 Provider。

## 15. 无障碍与适配

- 正文和关键状态满足 WCAG AA 对比度。
- 所有图标按钮提供语义标签。
- 图表提供文本摘要和逐点语义。
- 最小触控区域 `44 × 44 dp`。
- 时间、状态和单位不只依赖颜色。
- `360 × 800` 不得水平溢出。
- 大字体时卡片允许增高和换行。
- 横屏不是首版主要布局，但不得崩溃。
- 屏幕阅读器焦点顺序与视觉阅读顺序一致。
- 底部弹层打开后焦点进入弹层，关闭后回到触发控件。

3. 落地首页节奏轴与首页交互。
4. 改造趋势范围、图表探查和缓存键。
5. 改造简报具体日期与时间线。
6. 改造提醒筛选、分组和详情状态更新。
7. 改造“我的”感知状态、权限、勿扰和本地数据说明。
8. 补齐降级状态、无障碍和视觉回归测试。

每完成一个页面阶段，先通过对应 Widget 测试和同尺寸截图比较，再进入下一阶段。

## 20. 结论

`health-monitor-app-design.pen` 定义了当前产品的统一视觉方向：暖白画布、白色立体卡片、柔和维度色、结论优先和低打扰交互。

Flutter 落地时，应把设计稿中的视觉层级与项目现有真实数据、权限、提醒和隐私边界结合起来。最终实现必须做到：

- 看起来属于同一套产品
- 每个动作有清晰反馈
- 每个提醒可以解释
- 每种缺失状态可以降级
- 不为了还原视觉稿而制造虚假能力或数据
