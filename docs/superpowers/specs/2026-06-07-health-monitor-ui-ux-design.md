# 健康监测 App UI 与交互设计文档

日期：2026-06-07  
状态：待评审

## 1. 文档目标

本文档用于明确健康监测 App 首版 MVP 的界面设计与交互设计方向，作为产品设计文档的体验层补充。后续原型、视觉设计、Flutter 页面实现与动效设计，应优先遵循本文档。

## 2. 体验定位

本产品的 UI / UX 核心定位为：

`温和陪伴型健康助手`

这意味着产品不应呈现为：

- 冷冰冰的健康监测面板
- 医疗后台或诊断工具
- 充满预警感的行为监管系统

而应呈现为：

- 安静、可信、低打扰
- 像一个会理解用户日常状态的健康助手
- 用生活化语言解释数据与建议

## 3. 已确认的设计方向

当前已确认的关键设计决策如下：

- 产品气质：温和陪伴型
- 首页策略：结论与数据并重
- 视觉气质：柔和自然
- 首页主结构：陪伴感优先
- 顶部主卡：可展开洞察卡
- 主卡展开方式：半屏浮层
- 底部导航：三栏
  - 首页
  - 简报
  - 我

## 4. 首页设计

首页应首先回答一个问题：

`我今天状态怎么样？`

首页从上到下建议分为五个区域。

### 4.1 顶部欢迎区

作用：

- 提供情绪进入点
- 让产品显得有温度，而不是直接进入数据视图

内容建议：

- 时段问候，例如“早上好”“晚上好”
- 一句轻引导，例如“看看你今天的状态”
- 右上角保留一个轻入口，可用于通知或个人页快捷入口

要求：

- 视觉轻
- 不承担信息密度
- 不与主状态卡争主次

### 4.2 今日状态卡

今日状态卡是首页主角，也是产品最重要的识别点。

#### 默认态

默认态建议包含：

- 标签：例如“今天状态”
- 一句总结：例如“今天整体还不错，下午久坐有点集中”
- 一句最优先建议：例如“现在起身活动 3 分钟，会比补步数更有效”

默认态要求：

- 轻
- 温和
- 不堆砌细节
- 让用户在 3 秒内理解今天最重要的结论

#### 展开态

展开方式采用 `半屏浮层`。

展开后展示：

- 为什么系统得出当前判断
- 今天最主要的问题是什么
- 2 到 3 条次级观察
  - 下午 14:00 到 17:30 久坐明显
  - 今晚看手机次数偏多
  - 户外活动偏少，但还有补救空间
- 一个更具体的行动建议

展开态要求：

- 像“被解释清楚的助手结论”
- 不像一份分析报告
- 不要用技术术语和原始传感器语言

### 4.3 三大核心指标区

今日状态卡下方紧接三大核心指标：

- 步数
- 久坐时长
- 屏幕使用时长

设计建议：

- 使用 3 张小卡片并列展示，或 2 + 1 的自适应结构
- 每张卡片除了数值，还附一个短状态词
  - 偏少
  - 偏高
  - 正常
  - 稍多

目标：

- 让用户不用自己解释数字
- 用最少认知成本理解今天的基础状态

### 4.4 扩展洞察区

扩展洞察不应设计成二级 dashboard，而应设计成轻量洞察流。

可包含：

- 户外活动偏少
- 今晚看手机较频繁
- 低头用机时间偏长
- 今天移动中看屏 2 次

要求：

- 每条卡片像一句生活化提醒
- 不直接展示过多底层指标
- 强调“被理解”，而不是“功能很多”

### 4.5 今日建议区

首页底部建议放置 1 到 2 张建议卡。

建议文案应：

- 具体
- 低压
- 可马上执行

例如：

- “现在站起来活动 3 分钟，会比晚点补运动更容易做到。”
- “今晚如果把手机抬高一点看，会让颈肩轻松很多。”

不建议使用：

- 命令式语气
- 规则通知语气
- 医疗判断语气

## 5. 简报页设计

简报页的任务不是展示更多数据，而是帮助用户形成 `回顾感`。

建议采用：

`时间流 + 卡片日报`

### 5.1 单张日报卡结构

每张日报卡建议包含：

- 日期与一句总评
- 三大核心指标
- 活动节律总结
- 数字生活摘要
- 姿势或环境摘要
- 一条明日优先建议

示例：

- “今天活动偏少，但晚间有补回来一点”
- “上午状态平稳，下午久坐明显，晚饭后活动有所改善”
- “今晚看手机偏频繁，碎片化查看较多”

### 5.2 时间范围切换

首版建议支持：

- 今天
- 昨天
- 最近 7 天

首版不建议优先做重趋势图或复杂分析图表。

可以用轻量周总结代替复杂图表，例如：

- “这周你最常见的问题是下午久坐”
- “这周整体屏幕使用晚于 23:00 的情况偏多”

## 6. “我”页面设计

“我”页不是传统意义上的个人主页，而是：

`信任与控制中心`

用户来到这里，主要是想知道：

- 这个 App 看到了什么
- 为什么会提醒我
- 我能控制什么
- 我的隐私是否被妥善处理

### 6.1 我的提醒

展示：

- 今天提醒次数
- 最近一条提醒内容
- 进入提醒记录页的入口

提醒记录详情里应能看到：

- 触发时间
- 提醒文案
- 触发原因解释

### 6.2 权限与感知状态

展示：

- 活动识别：已开启 / 未开启
- 位置：已开启 / 未开启
- 麦克风环境噪音：已开启 / 未开启
- 数字生活习惯分析：已开启 / 未开启

原则：

- 不只显示“权限开关”
- 要让用户知道“这个能力是否正在参与分析”

### 6.3 隐私与数据说明

应提供明确入口，说明：

- 不保存原始音频
- 不上传原始传感器历史
- 数据主要在本地处理
- 关闭权限后会失去哪些能力

这一部分是产品信任感的重要来源。

### 6.4 提醒与显示偏好

首版建议提供少量调节项：

- 久坐提醒强度
- 夜间是否减少提醒
- 简报提醒时间
- 是否展示某些扩展洞察

不建议首版提供大量细碎开关，以免造成设置负担。

## 7. 视觉系统

整体视觉目标是：

`被温和照顾，而不是被持续监控`

### 7.1 色彩方向

建议采用“柔和自然”路线：

- 主背景：暖白、雾白
- 主色：浅鼠尾草绿、柔和苔绿、雾感青绿
- 辅助色：淡雾蓝、浅沙色、轻灰绿
- 提醒色：柔和琥珀、暖杏、低饱和砖橘

不建议：

- 高饱和撞色
- 大面积纯黑纯白
- 紫色科技感路线
- 医疗蓝大面积主导

### 7.2 卡片风格

建议：

- 大圆角，但不过度幼态化
- 轻边框
- 非重阴影
- 浅层背景与充足留白

层级建立方式优先依赖：

- 背景明度
- 字号层级
- 间距节奏

而不是依赖厚重阴影或强描边。

### 7.3 排版方向

建议：

- 总结性文案偏大、偏有情绪感
- 数字信息规整、清晰、适合扫读
- 解释性文案轻一点，不抢主信息

不建议：

- 整页字号都偏大
- 页面所有区域都在争注意力

### 7.4 图标与装饰

建议：

- 线性图标或轻填充图标
- 简洁、自然、低压
- 装饰元素可使用极轻的植物、晨昏渐变或抽象呼吸感背景

不建议：

- 过于尖锐的警示符号
- 大面积强情绪插画
- 幼态化角色作为主视觉

## 8. 动效方向

动效应服务于“呼吸感”和“陪伴感”，而不是炫技。

推荐使用在：

- 首页状态卡展开为半屏浮层
- 每日简报卡切换
- 指标刷新过渡
- 提醒解释展开

动效要求：

- 慢一点
- 柔一点
- 不弹跳
- 不做强炫技转场

## 9. 关键交互原则

### 9.1 默认轻，按需展开

用户首次看到的信息必须轻，深层分析按需展开。

适用到：

- 首页状态卡
- 简报补充说明
- 提醒原因解释

### 9.2 所有提醒必须可解释

每个提醒都必须能回答：

- 为什么现在提醒我
- 依据是什么

提醒体验至少要有两层：

- 提醒本身
- 提醒原因说明

### 9.3 一次只推动一个动作

首页与简报页中的建议应遵循：

- 一次只推一个最优先动作
- 建议要具体可执行
- 不堆积多条同级建议

### 9.4 始终保留控制感

用户应始终能理解和控制：

- 为什么看到这条结论
- 为什么收到这条提醒
- 哪些权限正在开启
- 关闭后会失去哪些能力

## 10. 首版原型建议画法

首版原型不应先追求页面数量，而应优先画清关键状态。

建议绘制顺序：

1. 首页默认态
2. 首页“今日状态卡”展开后的半屏浮层
3. 简报页单张日报卡
4. 简报页最近 7 天列表态
5. “我”页主入口结构
6. 提醒原因解释态
7. 权限未开启态
8. 数据不足时的空态 / 降级态

首版必须至少画清这四类状态：

- 默认态
- 展开态
- 解释态
- 空态 / 降级态

## 11. 总体结论

本产品的 UI / UX 设计不应以“展示监测能力多”为目标，而应以：

- 减少解释成本
- 增加被照顾感
- 保持低打扰
- 建立信任与控制感

为首要目标。

最终体验应更像：

`一个安静、可信、会解释自己的健康助手`

而不是：

`一个持续盯着用户行为的监测面板`

## 12. 下一步建议

本文档确认后，后续建议按以下顺序推进：

1. 基于本文档补 UI 原型稿
2. 将关键组件拆解为 Flutter 页面与组件清单
3. 补充空态、权限态、降级态的专门设计
4. 将视觉 token 与组件规范写入前端实现文档
