# 健康监测 App 多天连续使用验证清单

日期：2026-06-10
状态：待执行

## 1. Android 连续使用验证

- [ ] 连续 3 天前台使用后，本地存储未膨胀超过 50MB
- [ ] 连续 3 天后台采集后，通知常驻未因系统杀死而消失
- [ ] WorkManager 在设备重启后能在 15 分钟内重新调度
- [ ] 前台服务在低电量模式下降级为 30 分钟周期
- [ ] 应用被用户从最近任务划掉后，前台服务能在 1 分钟内自恢复

## 2. iPhone 连续使用验证

- [ ] 连续 3 天使用后，BGTaskScheduler 未出现连续拒绝
- [ ] 后台应用刷新关闭时，首页能正确展示「数据可能延迟」提示
- [ ] 低功耗模式下，采集间隔自动延长至 60 分钟以上
- [ ] App 从后台恢复时，日记账未出现重复条目

## 3. 弱权限验证

- [ ] 仅授予运动权限（拒绝位置）时，首页正常展示活动指标，位置显示「权限未开启」
- [ ] 仅授予位置权限（拒绝运动）时，首页正常展示户外时长，活动显示「数据不足」
- [ ] 所有权限均拒绝时，首页展示「开启权限以获取健康洞察」指引
- [ ] 权限在系统设置中被收回后，应用返回前台能自动刷新状态

## 4. 后台恢复验证

- [ ] Android 前台服务被系统杀死后，应用在前台打开时自动重启
- [ ] iPhone BGTaskScheduler 窗口期到达时，即使 App 未在前台也能执行一次采集
- [ ] 后台链路中断后，规则引擎输出标记为「数据可能不完整」
- [ ] 恢复后首轮采集结果在 30 秒内写入 Isar

## 5. 提醒触发与解释验证

- [ ] 久坐提醒在规则判定后的 5 分钟内触发本地通知
- [ ] 每条提醒在提醒记录页有完整的「原因」和「建议」字段
- [ ] 同类型提醒在 2 小时内不重复触发
- [ ] 用户在提醒上点击「忽略」后，24 小时内同类型不再触发

## 6. 耗电与性能验证

- [ ] Android 前台服务在 24 小时内耗电不超过 5% 电池容量
- [ ] iPhone 后台刷新单次执行不超过 30 秒 CPU 时间
- [ ] Isar 写入操作在主线程阻塞时间平均不超过 5ms
- [ ] 首页加载完成后内存占用不超过 200MB

## 7. 日志与诊断验证

- [ ] 采集状态每次变更都产生一条 INFO 级日志
- [ ] 后台链路中断时产生 WARNING 级日志
- [ ] 规则引擎输出包含所有维度的评估结果
- [ ] 权限变化事件记录 from/to 两种状态
