# 双平台能力验证清单

日期：2026-06-07  
更新：2026-06-09  
状态：阶段 0 正式版

## 使用方式

本清单不再记录“待验证问题”，而是记录当前可进入开发的正式结论。  
每项能力统一给出：

- Android 结论
- iPhone 结论
- 能力来源 / 开发路径
- 对 MVP 的影响
- 降级方案

结论枚举统一为：

- `支持`
- `受限`
- `不支持`

## 平台分层结论

- Android：`完整能力端`
- iPhone：`受限正式端`

这一定义意味着：

1. Android 负责承载完整数字生活习惯分析与更强后台连续性。
2. iPhone 必须是正式可用端，但允许用替代指标覆盖系统受限能力。
3. 页面层消费统一能力语义，不直接处理平台差异。

## 核心能力矩阵

### 1. 活动识别

- Android：`支持`
- iPhone：`支持`
- 能力来源 / 开发路径：Flutter `sensors_plus` 提供基础传感器流，必要时由原生层补强采样稳定性。
- 对 MVP 的影响：可作为首批真实能力进入活动识别与久坐提醒链路。
- 降级方案：若后台连续性不足，则先保留前台与短窗口采样。

### 2. 姿势 / 用机姿态

- Android：`支持`
- iPhone：`支持`
- 能力来源 / 开发路径：共享层消费加速度计 / 陀螺仪聚合结果，姿势判断逻辑保持纯 Dart。
- 对 MVP 的影响：可进入姿势风险与低头用机建议能力。
- 降级方案：若采样频率受限，则先输出较低分辨率姿势判断。

### 3. 位置摘要

- Android：`支持`
- iPhone：`支持`
- 能力来源 / 开发路径：优先使用 `geolocator`，再由平台层消化持续定位与后台差异。
- 对 MVP 的影响：可支撑位置摘要、通勤线索和活动上下文。
- 降级方案：拒绝位置权限后，仅保留无位置依赖分析。

### 4. 环境噪音等级

- Android：`支持`
- iPhone：`支持`
- 能力来源 / 开发路径：通过原生层或插件采集噪音等级，只保留等级结果，不保存原始音频。
- 对 MVP 的影响：可进入环境噪音摘要和提醒规则。
- 降级方案：无麦克风权限时关闭噪音能力，不影响其他能力运行。

### 5. 屏幕使用摘要

- Android：`支持`
- iPhone：`受限`
- 能力来源 / 开发路径：Android 可基于 Usage Stats；iPhone 侧只能基于系统允许范围内的替代线索。
- 对 MVP 的影响：数字生活能力必须从一开始就按双平台不对称设计。
- 降级方案：iPhone 统一走替代指标路径，不承诺 Android 同等级结果。

### 6. 应用类别使用偏好

- Android：`支持`
- iPhone：`不支持`
- 能力来源 / 开发路径：Android 基于 Usage Access 与系统应用使用摘要；iPhone 普通 App 不作为稳定交付能力承诺。
- 对 MVP 的影响：应用类别偏好是 Android 平台增强能力，不进入 iPhone 首版承诺。
- 降级方案：iPhone 使用活跃时段、查看频率、使用时长等替代指标。

### 7. 数字生活替代指标

- Android：`支持`
- iPhone：`支持`
- 能力来源 / 开发路径：共享层统一抽象“查看频率、活跃时段、使用时长”等摘要接口。
- 对 MVP 的影响：这是 iPhone 正式可用路径，也是 Android 权限拒绝后的降级出口。
- 降级方案：当全量数字生活数据不可用时，仍保留替代摘要输出。

### 8. 后台采集

- Android：`支持`
- iPhone：`受限`
- 能力来源 / 开发路径：Android 采用前台服务 + 后台任务；iPhone 采用系统允许范围内的 Motion / Location / Background 组合策略。
- 对 MVP 的影响：后台采集必须作为正式能力推进，但双平台实现强度不同。
- 降级方案：iPhone 或弱权限场景降级为以前台采集和短窗口刷新为主。

## 开发落地要求

1. Flutter 层必须通过统一能力矩阵消费这些结论。
2. 领域模型应至少覆盖：
   - 活动识别
   - 姿势风险
   - 位置摘要
   - 环境噪音
   - 屏幕使用摘要
   - 应用类别偏好
   - 数字生活替代指标
   - 后台采集状态
3. 权限页与设置页必须复用正式结论文案，避免单独维护另一套说法。
4. 所有“受限”能力都必须有明确替代路径；所有“不支持”能力都必须有范围边界说明。

## 当前结论摘要

- Android 可作为完整能力端继续推进真实数据闭环。
- iPhone 可作为受限正式端继续推进，但数字生活与后台连续性必须从第一天就按降级路径设计。
- 项目后续优先级应继续保持为：真实依赖 -> 领域模型 -> 存储层 -> 调试页 -> 第一条真实采集链路。
