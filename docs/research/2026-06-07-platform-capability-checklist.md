# 双平台能力验证清单

日期：2026-06-07

## 待验证能力

1. iPhone 是否允许普通 App 获取屏幕使用聚合能力
2. iPhone 是否允许普通 App 获取应用类别偏好
3. Android 是否可通过 Usage Stats 获取应用类别使用摘要
4. 双平台是否可稳定接入加速度计、陀螺仪、位置、麦克风噪音等级
5. 双平台后台采集限制对 MVP 的影响

## 每项结论格式

- 结论：支持 / 受限 / 不支持
- 证据：官方文档或平台权限说明
- 对 MVP 的影响
- 降级方案

## 当前初步判断

### 1. iPhone 屏幕使用聚合能力

- 结论：受限
- 证据：需继续核实 Apple 面向普通 App 的可用范围与 entitlement 限制
- 对 MVP 的影响：不能默认承诺 iPhone 侧可提供 Android 同等级的数字生活习惯摘要
- 降级方案：保留查看频率、活跃时段、屏幕活跃时长等可替代指标

### 2. iPhone 应用类别偏好

- 结论：不支持或高度受限
- 证据：需继续核实 Apple FamilyControls / DeviceActivity 相关能力的准入边界
- 对 MVP 的影响：iPhone 侧首版不能以“应用类别偏好”作为稳定交付能力
- 降级方案：用时段、频率、活跃时长替代

### 3. Android 应用类别使用摘要

- 结论：支持
- 证据：需基于 Android Usage Stats 官方文档继续细化权限与实现条件
- 对 MVP 的影响：Android 侧可承载更完整的数字生活习惯分析
- 降级方案：若权限被拒绝，则退化为仅展示基础用机时段与频率

### 4. 基础传感器与位置、噪音等级

- 结论：基础能力支持，后台连续性需单独验证
- 证据：需在 Flutter 插件能力与原生实现边界上继续核实
- 对 MVP 的影响：活动识别、姿势风险、位置摘要与环境噪音可进入 MVP
- 降级方案：先做前台或短窗口采样，后台稳定性后置验证

### 5. 后台采集限制

- 结论：双平台均受限，且策略不同
- 证据：需继续核实 Android WorkManager / 前台服务与 iPhone 后台刷新策略
- 对 MVP 的影响：后台采集不可在首阶段当作理所当然能力处理
- 降级方案：先跑通前台与短周期更新，再逐步补后台策略

## 后续补证方向

- Apple FamilyControls / DeviceActivity 官方文档
- Android UsageStatsManager 官方文档
- Flutter 平台通道与后台 isolate 官方文档
- geolocator、sensors_plus、权限相关插件与原生限制说明
